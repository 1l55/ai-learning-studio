# 03.04 · 一条任务，怎样变成页面内容？

副标题：读懂变量、对象与数组，从修改一个值开始。

课程位置：大纲 v3，模块 03「计算机与最小代码阅读能力」。目标：L2 理解与 L3 应用。

状态：实验区视觉原型已获用户确认，交互网页与独立练习包已实现；本例真实 Codex 桌面操作图尚未采集。以下为教学内容与制作依据。核对日期：2026-10-15。

## 开始前：这节课不需要你先会什么

你不需要背代码，也不需要安装编程语言。先读完例子，再在配套实验中选目标、改一个值、看结果。独立 Codex 操作需要能打开练习项目；尚未完成环境准备，可以先学习正文。

如果你已经做过任务清单，可能遇到过这些问题：改了文字，刷新却变回去；完成一条任务，另一条也被改了；页面上有两条同名任务，无法说清要修改哪条。

本节先解决其中一个基础：**程序里用什么表示“一条任务”，又怎样从一组任务中找到它。** 页面更新和保存机制会指出职责边界，后续课程再展开实现。

学完请用证据回答三件事：

- 能在一小段数据中找到某条任务的标题和完成状态。
- 能预测修改某个字段后，哪些内容应该变，哪些应该保持。
- 能向 Codex 指定一条同名任务，修改后检查另一条没有受影响。

## 01 · 先猜一猜：同一个标题，是同一条任务吗？

页面上有两行：

| 识别标记 | 标题 | 完成状态 |
| --- | --- | --- |
| t01 | 读一章书 | 未完成 |
| t02 | 读一章书 | 未完成 |

它们可能分别是今天和明天的读书安排。为了让你看清对应关系，练习会显示识别标记；真实产品不一定把它展示给使用者。

先判断：你要把 **t02 的标题改成“读第二章”**，应该怎样描述？

| 选项 | 判断内容 |
| --- | --- |
| A | 找到标题为“读一章书”的任务，把标题改成“读第二章”。 |
| B | 找到 ID 为 t02 的任务，只改它的标题，保留其他字段与另一条任务。 |
| C | 找到列表第二个位置，修改标题；即使排序改变，也继续使用第二个位置。 |

## 02 · 看懂原理：一个值、一条记录、一组记录

### 2.1 变量：给程序里用到的值一个名字

先只看一行：

```javascript
// example: variable
const title = "读一章书";
```

从左到右读：用 `const` 声明一个名叫 `title` 的变量，让它关联文字“读一章书”。双引号中的内容是**字符串**，也就是文本值；这里的 `title` 是程序里的名字，不是直接显示在页面上的中文标签。

你可以暂时把名字看作寻找值的标签。这个类比只帮助阅读：变量不是磁盘里的一个文件，声明也没有替你创建输入框或保存记录。`const` 在这里限制后续给这个名字重新指定另一个值；它并不保证关联对象的内部内容不能改变，后面会用一个反例说明。[语言依据：MDN const](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Statements/const)

### 2.2 对象：把同一件事的相关信息放在一起

任务不只有标题，还要知道是哪一条、有没有完成：

```javascript
// example: object
const task = {
  id: "t01",
  title: "读一章书",
  done: false
};
```

大括号 `{ }` 围住了一个**对象**。在这个例子中，它把一条任务的相关信息组织在一起。每一项由名字和对应的值组成：

| 写法 | 本例中的意思 | 修改前要问什么 |
| --- | --- | --- |
| `id: "t01"` | 识别这条记录的标记 | 我是否找到了正确的任务？ |
| `title: "读一章书"` | 显示给使用者的标题 | 只想改文字，还是连任务身份也要变？ |
| `done: false` | 目前未完成 | 本次是否应该改变完成状态？ |

这里把这些属性称为“字段”，方便与表格中的一列对应。对象也能表示其他事物，并非每个对象都是任务记录。属性名、冒号、值之间的关系，可以对照 [MDN 对象基础](https://developer.mozilla.org/en-US/docs/Learn_web_development/Core/Scripting/Object_basics) 回看。

`false` 和 `true` 是**布尔值**，表达两种逻辑状态。本练习约定 `false` 为未完成，`true` 为已完成。引号里的 `"false"` 则是文本，不能在需要布尔值的位置随意替换。字段名 `done` 是项目采用的约定；换成 `completed`，读取它的代码也必须采用相同约定。

### 2.3 数组：让多条任务成为一组有顺序的数据

```javascript
// example: array
const tasks = [
  { id: "t01", title: "读一章书", done: false },
  { id: "t02", title: "读一章书", done: false }
];
```

方括号 `[ ]` 围住一个**数组**，里面依次放了两个对象。`tasks` 是整组数据的变量名，每对大括号是其中一条记录。这里用英文复数帮助人阅读；给变量加上 `s` 不会自动让它变成数组。

逐层读：一组任务 `tasks` → 其中一条任务 → 那条任务的某个字段。数组按位置访问元素，JavaScript 的位置编号从 `0` 开始，叫作**索引**：第一条是 `tasks[0]`，第二条是 `tasks[1]`。这解释的是访问规则，不意味着第一条的 ID 必须是 0。[语言依据：MDN 数组](https://developer.mozilla.org/en-US/docs/Learn_web_development/Core/Scripting/Arrays)

### 2.4 用一行小改动，读出目标和范围

下面是独立的教学片段，先预测，不用急着运行：

```javascript
// example: update-title
const tasks = [
  { id: "t01", title: "读一章书", done: false },
  { id: "t02", title: "读一章书", done: false }
];
tasks[1].title = "读第二章";
```

从左往右：找到 `tasks` 的索引 1，也就是当前第二个对象；点号后的 `title` 指定其标题字段；赋值让这个字段得到新文本。逗号没有把两条记录合成一条；本例分别创建了两个对象。

<details>
<summary>展开本例的预期数据</summary>

| 记录 | 标题 | 完成状态 |
| --- | --- | --- |
| t01 | 读一章书 | 未完成 |
| t02 | 读第二章 | 未完成 |

只有 t02 的标题改变。它的 ID 和完成状态，以及 t01 的全部字段，都应保持。

</details>

这里按位置操作，是为了读懂语法。实际创作要先按稳定 ID 定位目标；排序以后不能继续假定索引 1 就是 t02。怎样写查找和处理函数，在下一课展开，本课先通过带标注的实验观察。

### 2.5 标题、索引和 ID：内容、位置、身份

把两条记录的顺序交换后，第一条变成 t02，第二条变成 t01。它们移动了位置，身份没有因为移动而改变。

| 你用来寻找的依据 | 排序后会怎样 | 使用边界 |
| --- | --- | --- |
| 标题“读一章书” | 两条仍可能同名 | 可用于搜索，不能假定唯一。 |
| 当前第二个位置 | 可能已经换成另一条任务 | 适合读取当前顺序，不能独立承担稳定身份。 |
| ID 为 t02 | 仍可识别那条记录 | 前提是系统正确生成、保留并检查唯一性。 |

ID 也不是权限证明。知道一条记录的 ID，不代表有权读取或修改它；用户隔离留到模块 10 实际验证。

### 2.6 数据改变、页面更新、刷新保留，是不同的动作

你刚才修改的是 JavaScript 中的数据。页面要反映这个变化，还需要负责显示的代码更新浏览器里的页面结构；这个过程常称为**渲染**。在本课实验中，“运行并核对”会执行选定操作，然后重新绘制预览，因此你能同时观察数据与页面的对应关系。

另一种程序可能改了数据却没有更新显示。反过来，只在浏览器检查工具中改一行可见文字，也不等于改了程序的任务数据。浏览器用 DOM 表示可操作的页面结构；本节先认识它与数据的区别，不要求手写 DOM 操作。[机制依据：MDN DOM](https://developer.mozilla.org/en-US/docs/Web/API/Document_Object_Model)

保存还需要额外机制：修改运行中的记录，不会自动写回源文件；重新加载若重新执行初始数据，就会回到起点。浏览器持久保存、服务端保存和跨设备同步在模块 07—09 分别讲解。本课实验刻意不保存任务修改，刷新后恢复初始数据；学习记录是另一份数据，不能用“我的答案还在”证明“任务已经保存”。

### 深入一点：为什么 const 对象还能修改？

```javascript
// example: const-object
const task = { id: "t01", title: "读一章书", done: false };
task.done = true;
```

这段操作没有给变量 `task` 重新指定另一个对象，而是修改当前对象里的一个字段，因此可以执行。`const task` 不等于“这条任务的所有内容被冻结”。

两个名字或两个数组元素也可能引用同一个对象；那时通过其中一个修改，会从另一处看到变化。本课初始数据是两个分别创建的对象；不要把本例“只变一条”推广成所有代码的保证。判断真实项目时，应检查创建和引用关系。这个深入问题可以回访，不作为第一次实验的前置条件。

## 03 · 动手实验：先预测，再观察对应关系

以下对应交互网页中的操作说明与反馈内容。实验采用确定的本地数据操作，不调用模型、不评判自由文本解释、不运行学习者输入的任意代码。

### 实验一：只改一条任务的标题

起点：两条同名任务 t01、t02，都是未完成。依次选择：目标 t02、字段 `title`、新值“读第二章”。输入框里的新值此时只是草稿，当前数据和页面暂时不变。

选择你的预测，再点“运行并核对”：

- 只改 t02 的标题。
- 两条任务的标题都变。
- t02 的标题和完成状态一起变。

未选择预测时，提示“先选一个预测，再运行观察”。不要让按钮在没有解释的情况下失效。

运行后显示实际改动，并对照目标和未改动项。正确预测反馈：“本次只更新了 t02 的 title。请再核对 t01、两个 ID 和 done 都没改变。”其余两项分别反馈：“同名不等于同一个对象；本次按 ID 定位 t02。”“改标题并没有给 done 赋新值；请区分字段的职责。”预测错误仍运行，让学习者看到反证后再尝试。

### 实验二：改变完成状态，保留标题

恢复初始数据；选择 t01 的 `done`，通过“已完成 / 未完成”选择真实布尔状态，不要求学习者手输 `true`。

先预测：会变化的是 t01 的勾选状态，还是两条标题？运行后核对：t01 的 `done` 为 `true`，预览显示已完成；t02 仍未完成，两条标题和两个 ID 不变。完成标记必须有文字说明，不能只依赖颜色。

### 实验三：增加一条记录，观察“一组”怎样变大

恢复起点；进入同一实验区的“增加记录”任务，使用给定的新 ID t03 和标题“整理桌面”，默认未完成。这里先使用已准备的数据，ID 自动生成与校验属于后续实现问题。

预测后运行：数组多了第三个对象，预览多了一行；原来两条记录没有改名或消失。再提交同一个 t03，应提示“这个 ID 已存在，原数据未改变”，不能悄悄覆盖。

### 实验四：位置改变以后，仍然修改同一条任务

恢复起点；选择“对调顺序”。这次操作也先预测：记录数量和字段不变，前后位置交换。

然后把 ID 为 t02 的标题改成“读第二章”。它此时位于第一行，仍应正确修改。最后在旁边的“如果按索引 1 修改”对照演示中观察：当前第二行是 t01。对照演示使用独立副本，不覆盖你的实验结果。

每轮都问自己：目标是谁、改哪个字段、哪项证据能证明另一条没受影响？

### 如果结果没有符合预测

先核对是否点击了运行、是否恢复过数据、当前顺序有没有变化。再对照 ID、字段和新值，不要一看到错误就同时改好几个条件。每轮可恢复固定起点，帮助你确认差异来自哪一步。

## 04 · 到 Codex 中做一次可核对的小修改

网页实验帮助你认识关系。接下来把同样的判断用到一个独立练习文件中，才能检查自己是否会与 Codex 协作。

### 4.1 起点与边界

使用课程配套的独立练习项目，内有可以显示两条任务的页面和上面同结构的初始数据。不在私人项目中试错，不安装与本课无关的依赖，不新增数据库或联网服务。配套文件已位于 ai-learning-mvp/examples/data-literacy，可复制整个目录或下载网页提供的练习包；解压后打开 index.html 即可运行。

先确认当前练习目录，再让 Codex 读取页面与任务数据。读完后请它指出：数据在哪个文件、由哪段代码显示；如果没有找到，应说明实际读到了什么，而非继续猜。

### 4.2 第一次只请它解释

可复制的任务说明：

> 请只阅读当前练习目录，先不要修改。找到两条任务的数据和负责显示它们的代码，用中文指出 tasks、每条任务对象、id、title、done 的用途。说明你实际读取的文件路径，给出与解释有关的短代码。指出哪一项决定任务身份，哪一项只是当前显示文字。

核对它引用的文件真实存在、字段与练习一致。不要仅凭回答“我明白了”继续。

### 4.3 提出小改动，并检查没有扩大范围

> 请只把 ID 为 t02 的任务标题改为“读第二章”。保留它的 ID 和 done，保留 t01 的全部字段和两条记录的数量。不要按标题批量替换，不要改变布局或引入新功能。说明修改的是初始数据、运行状态还是保存的数据，并给出我应该怎样打开和检查结果。

对照文件差异阅读改变的那一处。官方文档说明，本地审阅窗反映 Git 仓库的改动范围，可能包含其他来源的修改；因此先核对当前文件和范围，不能把窗中全部变化都当作这一次任务产生的变化。[操作依据：OpenAI 本地改动审阅说明](https://learn.chatgpt.com/docs/code-review?surface=app#what-changes-it-shows)

运行后，至少核对两条任务。若修改的是源文件中的初始数据，重新载入该文件时通常会读到新标题；若项目会用保存的数据覆盖初始数据，应先确认实际数据来源。本课配套练习不启用持久存储，以减少初次操作的分支。

### 4.4 换个条件再做，检查是否只会照做

先保存可恢复的练习副本，再把两条任务顺序对调。向 Codex 提出：把 t02 的完成状态设为已完成，保留标题、ID、顺序和 t01。

这次不再提供完整步骤。应能检查：即使 t02 已是第一行，也只改变它的 done；“改对了当前第二行”不构成通过。

### 4.5 保留证据，描述自己仍不理解的部分

| 要交出的证据 | 自己核对什么 |
| --- | --- |
| 修改前后相关数据或差异 | 目标准确，没有多改字段或记录。 |
| 运行后的两条任务 | 数据变化确实显示，另一条保持。 |
| 调序后的再次修改 | 定位依赖身份，能够适应位置变化。 |
| 一段自己的说明 | 解释变量、对象、数组和页面分别负责什么。 |

课内可以记录“我已自行验收”。系统不会因为你看完截图或复制过提示词，就自动确认你完成了 Codex 操作。
