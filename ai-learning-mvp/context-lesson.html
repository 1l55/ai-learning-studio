AI 为什么会
答非所问？

理解上下文，把脑海里的想法变成清楚的需求。

01

说清楚需求，会改变什么？

比较下面两种描述，再做出你的判断。

A.
“帮我做一个好用的任务管理工具。”

只表达愿望

“好用”可能意味着操作简单，也可能意味着功能丰富；个人清单和团队系统都可能符合这句话。

B.
“给我自己用，能添加任务、标记完成，关闭页面后任务仍然保留。”

补充目标与功能

使用者、核心操作和保存要求更明确了。不过怎样保存、要不要跨设备同步，还需要进一步说明。

没有说清楚的部分，AI 会怎样处理？
先思考，再揭晓。答错也可以重新尝试。
带着这个问题往下学

模型不知道哪些细节是你“默认它应该知道”的。你需要做的，是把会改变结果的区别表达出来，并确认双方理解一致。

02

上下文，是这次回答能参考的信息

先分清“它学过什么”与“它现在拿到了什么”。

你请一位设计师“做个任务工具”。如果没有告诉他谁来用、要解决什么问题，他只能先问你，或者根据经验作出一些假设。你看到成果后才说“我只想自己用，不需要登录”，双方就需要返工。

这个例子帮助我们理解信息不足，但有一个边界：大模型不是在用人的头脑猜你的心思。它利用训练中学到的模式，结合本次输入逐步生成内容；编程助手还可能先读取文件、调用工具，再把得到的信息用于后续生成。

1. “上下文”具体包括什么？

在这里，上下文指模型本次生成时可以利用的输入信息。它可能包括当前要求、产品提供的规则、仍被纳入的历史对话、已读取的文件、图片，以及工具返回的内容。你屏幕上看见的全部聊天记录，不一定等于模型这一次实际拿到的完整输入。

当前要求相关对话已读取资料工具结果共同影响这一次的生成

比如你提出“关闭后任务还在”，这约束了保存行为；你再补充“只在当前浏览器使用，不要求同步”，就进一步缩小了实现范围。信息本身没有替你完成代码，但减少了模型需要自行补全的决定。

2. 知识、上下文和记忆，分别是什么？

训练中学到的知识与模式
模型经过训练形成的能力。例如它可能知道网页常见的保存方式。给它发一段新需求，通常是在提供本次输入，不是在当场重新训练模型。
本次可用的上下文
这一次生成能参考的具体信息。例如“个人使用”“不需要登录”“刷新后保留任务”。模型熟悉任务工具，并不等于知道你的项目要求。
产品保存的记录或记忆
这是产品层面的保存和检索机制。记录需要被选取、读取或整理进当前工作过程，才能影响本次回答；具体方式因产品而异，不能一概当作永久、完整的记忆。

实用判断：不要只问“我以前说过没有”，还要问“这次有没有可靠依据表明，它参考了正确的那份信息”。

3. 为什么聊了很久，它仍会漏掉要求？

模型一次能处理的信息有容量限制，通常用 计量。你可以把上下文窗口暂时想成一张有面积限制的工作台：对话、资料和任务都要占位置，输出也需要空间。

工作台只是类比。真实容量不是按文件数或聊天条数计算；不同系统可能选取、截断或压缩历史信息。压缩有助于继续长任务，但摘要不是逐字保留的原始记录。即使信息仍在可用范围内，模型也可能遗漏或错误使用它，因此“放进去”不等于“已经准确用到”。

对你的项目，更稳妥的做法是保存一份简短的当前需求：目标、确定的功能、关键限制、验收条件。需求变化时更新它；遇到偏差时，指出哪一项被遗漏，让 Codex 先复述再继续。

4. 上下文为什么不是越多越好？

你真正需要的是足够、相关、清楚且互不冲突的信息。十页无关历史可能没有回答“任务存在哪里”；一段明确的保存要求却能直接支持实现决定。旧需求和新需求一起出现时，也要标明哪个有效。

有帮助的补充

“这是个人清单，无需登录；任务只存当前浏览器。刷新后，任务和完成状态要保留。”

仍有歧义的补充

“做得专业一点、智能一点，我之前见过一个特别好用的。”——它没有说明具体功能和验收方式。

5. 需求清楚之后，还需要验证吗？

需要。上下文能减少部分信息缺口，不能保证代码正确，也不能保证所有要求都被执行。你仍要运行作品、逐项检查。例如“刷新后还在”就应真的添加任务、标记完成、刷新，再核对两种状态。

如果描述已经清楚，结果仍不对，就继续排查：资料是否实际读取？要求是否冲突？代码是否有错误？不要把所有问题都归因于“提示词写得不好”。

      本课术语手册
      上下文 · Context
      模型本次生成可利用的具体输入信息。可能包括指令、相关对话、已读取资料和工具结果；它不自动等于所有历史记录。
      Token
      模型处理文本时使用的片段单位，可能是一个词、词的一部分或其他字符组合。中文里不能固定地把一个字当成一个 Token。
      上下文窗口 · Context window
      一次请求可处理的 Token 容量。输入、输出以及某些模型的推理内容都可能占用容量，具体以模型与产品说明为准。
      推理 · Inference
      在这里指使用训练好的模型处理输入并产生输出的过程，不等同于重新训练模型，也不保证推断正确。
      上下文压缩 · Compaction
      用更少的信息表示此前工作中的重要状态，以继续长任务。它不是逐字保留所有历史的承诺。
      验收条件
      可以实际观察或测试的完成标准。例如“刷新后任务和完成状态仍保留”，比“做得好用一点”更容易检查。
