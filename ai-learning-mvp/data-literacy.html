同一个标题，是同一条任务吗？

从一个实际问题开始，不需要先背语法。

第一次读代码？先看起点与本课目标

你不需要背代码，也不需要安装编程语言。先读完例子，再在配套实验中选目标、改一个值、看结果。独立 Codex 操作需要能打开练习项目；尚未完成环境准备，可以先学习正文。

如果你已经做过任务清单，可能遇到过这些问题：改了文字，刷新却变回去；完成一条任务，另一条也被改了；页面上有两条同名任务，无法说清要修改哪条。

本节先解决其中一个基础：程序里用什么表示“一条任务”，又怎样从一组任务中找到它。 页面更新和保存机制会指出职责边界，后续课程再展开实现。

学完请用证据回答三件事：

  • 能在一小段数据中找到某条任务的标题和完成状态。
  • 能预测修改某个字段后，哪些内容应该变，哪些应该保持。
  • 能向 Codex 指定一条同名任务，修改后检查另一条没有受影响。

02

一个值、一条记录、一组记录

每次只读与当前问题有关的一小段。

2.1 变量：给程序里用到的值一个名字

先只看一行：

const title = "读一章书";

从左到右读：用 const 声明一个名叫 title 的变量，让它关联文字“读一章书”。双引号中的内容是字符串，也就是文本值；这里的 title 是程序里的名字，不是直接显示在页面上的中文标签。

你可以暂时把名字看作寻找值的标签。这个类比只帮助阅读：变量不是磁盘里的一个文件，声明也没有替你创建输入框或保存记录。const 在这里限制后续给这个名字重新指定另一个值；它并不保证关联对象的内部内容不能改变，后面会用一个反例说明。语言依据：MDN const

2.2 对象：把同一件事的相关信息放在一起

任务不只有标题，还要知道是哪一条、有没有完成：

const task = {
  id: "t01",
  title: "读一章书",
  done: false
};

大括号 { } 围住了一个对象。在这个例子中，它把一条任务的相关信息组织在一起。每一项由名字和对应的值组成：

写法本例中的意思修改前要问什么
id: "t01"识别这条记录的标记我是否找到了正确的任务？
title: "读一章书"显示给使用者的标题只想改文字，还是连任务身份也要变？
done: false目前未完成本次是否应该改变完成状态？

这里把这些属性称为“字段”，方便与表格中的一列对应。对象也能表示其他事物，并非每个对象都是任务记录。属性名、冒号、值之间的关系，可以对照 MDN 对象基础 回看。

false 和 true 是布尔值，表达两种逻辑状态。本练习约定 false 为未完成，true 为已完成。引号里的 "false" 则是文本，不能在需要布尔值的位置随意替换。字段名 done 是项目采用的约定；换成 completed，读取它的代码也必须采用相同约定。

2.3 数组：让多条任务成为一组有顺序的数据

const tasks = [
  { id: "t01", title: "读一章书", done: false },
  { id: "t02", title: "读一章书", done: false }
];

方括号 [ ] 围住一个数组，里面依次放了两个对象。tasks 是整组数据的变量名，每对大括号是其中一条记录。这里用英文复数帮助人阅读；给变量加上 s 不会自动让它变成数组。

逐层读：一组任务 tasks → 其中一条任务 → 那条任务的某个字段。数组按位置访问元素，JavaScript 的位置编号从 0 开始，叫作索引：第一条是 tasks[0]，第二条是 tasks[1]。这解释的是访问规则，不意味着第一条的 ID 必须是 0。语言依据：MDN 数组

2.4 用一行小改动，读出目标和范围

下面是独立的教学片段，先预测，不用急着运行：

const tasks = [
  { id: "t01", title: "读一章书", done: false },
  { id: "t02", title: "读一章书", done: false }
];
tasks[1].title = "读第二章";

从左往右：找到 tasks 的索引 1，也就是当前第二个对象；点号后的 title 指定其标题字段；赋值让这个字段得到新文本。逗号没有把两条记录合成一条；本例分别创建了两个对象。

展开本例的预期数据
记录标题完成状态
t01读一章书未完成
t02读第二章未完成

只有 t02 的标题改变。它的 ID 和完成状态，以及 t01 的全部字段，都应保持。

这里按位置操作，是为了读懂语法。实际创作要先按稳定 ID 定位目标；排序以后不能继续假定索引 1 就是 t02。怎样写查找和处理函数，在下一课展开，本课先通过带标注的实验观察。

2.5 标题、索引和 ID：内容、位置、身份

把两条记录的顺序交换后，第一条变成 t02，第二条变成 t01。它们移动了位置，身份没有因为移动而改变。

你用来寻找的依据排序后会怎样使用边界
标题“读一章书”两条仍可能同名可用于搜索，不能假定唯一。
当前第二个位置可能已经换成另一条任务适合读取当前顺序，不能独立承担稳定身份。
ID 为 t02仍可识别那条记录前提是系统正确生成、保留并检查唯一性。

ID 也不是权限证明。知道一条记录的 ID，不代表有权读取或修改它；用户隔离留到模块 10 实际验证。

2.6 数据改变、页面更新、刷新保留，是不同的动作

你刚才修改的是 JavaScript 中的数据。页面要反映这个变化，还需要负责显示的代码更新浏览器里的页面结构；这个过程常称为渲染。在本课实验中，“运行并核对”会执行选定操作，然后重新绘制预览，因此你能同时观察数据与页面的对应关系。

另一种程序可能改了数据却没有更新显示。反过来，只在浏览器检查工具中改一行可见文字，也不等于改了程序的任务数据。浏览器用 DOM 表示可操作的页面结构；本节先认识它与数据的区别，不要求手写 DOM 操作。机制依据：MDN DOM

保存还需要额外机制：修改运行中的记录，不会自动写回源文件；重新加载若重新执行初始数据，就会回到起点。浏览器持久保存、服务端保存和跨设备同步在模块 07—09 分别讲解。本课实验刻意不保存任务修改，刷新后恢复初始数据；学习记录是另一份数据，不能用“我的答案还在”证明“任务已经保存”。

深入一点：为什么 const 对象还能修改？ 
const task = { id: "t01", title: "读一章书", done: false };
task.done = true;

这段操作没有给变量 task 重新指定另一个对象，而是修改当前对象里的一个字段，因此可以执行。const task 不等于“这条任务的所有内容被冻结”。

两个名字或两个数组元素也可能引用同一个对象；那时通过其中一个修改，会从另一处看到变化。本课初始数据是两个分别创建的对象；不要把本例“只变一条”推广成所有代码的保证。判断真实项目时，应检查创建和引用关系。这个深入问题可以回访，不作为第一次实验的前置条件。

      本课术语
      变量
      程序中用名字关联一个值；名字不会自动成为页面或文件。
      对象与字段
      对象可组织一条记录的相关信息；本例的 id、title、done 是职责不同的字段。
      数组与索引
      数组组织一组有序元素；索引是当前位置编号，从 0 开始。
      ID
      用来识别记录的标记；需要正确保留与保证唯一，不自动提供访问权限。
      布尔值
      true / false 两种逻辑状态，不等于引号中的同名文字。
      渲染与保存
      渲染更新可见页面；保存让数据在约定范围内重新载入。数据变化不自动完成这两件事。
